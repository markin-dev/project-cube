# Демо-сцена со всеми модельками и переключение сцен

Дата: 2026-10-15. Статус: согласовано, в работе.

## Задача

Отдельная демонстрационная сцена, где все модельки игры статично стоят на полу,
и переключатель между сценами (игра / демо) в панели настроек.

Согласовано с пользователем:
- В демо-режиме игра ставится на паузу: волны, стрельба, искры и звук не идут,
  при возврате к «Игре» продолжается с того же места.
- `SCENE_MODE` — обычный параметр конфига: сохраняется в localStorage,
  считается в «изменено: N», попадает в «Скопировать изменения».

## Что показывает демо-сцена

Все модельки, которые есть в игре, — одной линейкой вдоль экранной горизонтали:

1. куб игрока (`PLAYER_SIZE`);
2. пять типов врагов (tiny…brute, размеры и цвета из `ENEMY_KINDS`);
3. призрак — куб типа normal с материалом призрака (`CORPSE_MATERIAL`);
4. обычный снаряд и крит-снаряд (крит — увеличенный и крит-цветной);
5. полоска здоровья над врагом normal с частичным здоровьем (~60%);
6. две статичные кучки искр — обычные и крит-искры.

Цифры урона — HTML, не 3D-моделька, в демо не показываются. Стенки границы смерти
в демо не включаются (модельки «просто стоят на полу»).

Всё статично на полу (центр куба на `size / 2`), физика не участвует.
Размеры читаются при создании (как у «· новые»/«· перезагрузка»), цвета — live:
демо использует общие материалы игры, поэтому все `refresh*` из `applyLiveConfig`
действуют на него сразу.

## Устройство

### Новый модуль `src/demo-scene.ts`

- `SCENE_MODE_OPTIONS` — варианты для селекта панели: «Игра» / «Демо (модельки)»
  (по образцу `TONE_MAPPING_OPTIONS`).
- `createDemoScene({ camera })` → `{ scene, refresh }`: собственный `THREE.Scene`
  (фон, пол, свой свет через `createLights()`), модельки линейкой, см. выше.
- `refresh()` (зовётся из `applyLiveConfig`): фон, свет, цвет и размер кучек искр,
  пересборка материалов при смене тонмаппинга/теней (по образцу `refreshSceneLook`,
  со своим запоминанием прошлого состояния).
- Линейка: направление `(1, 0, −1)/√2` (горизонталь экрана в изометрии), шаг
  подбирается по размеру арены, чтобы вся линейка влезала в видимую камерой область.

### Экспорты-фабрики из существующих модулей

Чтобы демо строилось из тех же материалов и геометрий, а не дублировало их:

- `scene.ts` → `createFloor()` (пол на общем `FLOOR_MATERIAL`); `createScene` использует его;
- `player.ts` → `createPlayerCube()`; `createPlayer` использует её;
- `enemies.ts` → `createEnemyCube(kindName)`; `spawnEnemy` использует её;
- `corpses.ts` → `applyCorpseLook(cube)`; `turnIntoCorpse` использует его;
- `projectiles.ts` → `createProjectileMesh(isCrit)` (считает visualSize сам);
  `fireOneProjectile` использует её;
- `sparks.ts` → `getSparkColor(isCrit)` (чистая функция цвета);
- `hp-bar.ts` — уже экспортирует всё нужное (`createHpBar`, `setHpBarValue`, `turnToCamera`).

### Переключение

- `config.ts`: `SCENE_MODE: 'game'` — обычная строка конфига.
- `settings-panel.ts`: новая первая секция «Сцена» с селектом
  `{ key: 'SCENE_MODE', options: SCENE_MODE_OPTIONS }` (автоматически попадает
  в `PANEL_CONFIG_KEYS` — юнит-тест панели покроет сам).
- `post.ts`: `render(scene)` — рендерит переданную сцену (и в bloom-цепочке, и напрямую).
- `main.ts`:
  - `createDemoScene({ camera })`; `applyLiveConfig` зовёт `demoScene.refresh()`;
  - в цикле кадров при `SCENE_MODE === 'demo'`: шаги симуляции, синхронизация
    объектов, поворот полосок, пул света и `sparks.sync` пропускаются (пауза),
    рисуется демо-сцена; иначе — всё как раньше;
  - клик/пробел не перезапускают игру, пока включено демо.

## Тесты

- `unit/demo-scene.test.ts` — структура демо-сцены (модельки на полу `y = size/2`,
  линейка вдоль `(1, 0, −1)` с равным шагом), `refresh` (фон, свет, цвет/размер искр),
  экспорты-фабрики (материал, масштаб, тени, крит-размер).
- Панель: существующий тест `unit/settings-panel.test.ts` сам проверит `SCENE_MODE`.
- E2E (`browser/`): переключение селектом панели на демо останавливает движение
  врагов, обратное переключение возобновляет.
- Визуальная проверка скриншотом (playwright + swiftshader).
