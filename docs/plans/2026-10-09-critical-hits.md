# Криты: шанс, множитель урона, заметный визуал и физика

Дата: 2026-10-09
Статус: реализован, на прод не выложен

Отличия от исходного плана: реализовано ровно по плану; в тесты регрессии
(`damage-range`, `projectile-count`) добавлено явное `CRIT_CHANCE: 0` — они старше критов
и меряют базовый урон/логику добивания, а дефолтные 15% критов их «засоряли».

## Идея (от пользователя)

Критические попадания: базовый шанс 15%, базовый урон ×2, всё настраивается. Визуал — текст
критов другого цвета (и крупнее, по согласованию), искры критов другого цвета, в большем
количестве, крупнее и быстрее (отдельные множители, по согласованию). Физика — крит-снаряд
тяжелее и сильнее отбрасывает врага. Звук крита — не делаем (отдельной задачей потом).

## Как устроено сейчас (вход в решение)

- Урон снаряда бросается **при выстреле** (`rollDamage` в projectiles.ts) и тянется снарядом
  в полёте; `getIncomingDamage` складывает фактические урон летящих снарядов, чтобы `findTargets`
  не стрелял в уже «получающих своё» врагов.
- Искры — пул в `sparks.ts`, все экземпляры рисуются **одним** `THREE.InstancedMesh` с общим
  `SPARK_MATERIAL`; цвет один на все искры (`refreshColor` перекрашивает материал).
- Цифры урона — HTML-дивы в `damage-numbers.ts`, стиль инлайном из конфига.
- Попадание — `applyHit` в main.ts: искры → урон (`hitEnemy`) → цифра → звук → смерть.

## Решение

### 1. Бросок крита — при выстреле, вместе с уроном

В `fireOneProjectile`: `isCrit = Math.random() < config.CRIT_CHANCE`. Если крит —
`damage = Math.round(rollDamage() × config.CRIT_MULTIPLIER)`. Снаряд несёт флаг `isCrit`
в `Projectile` (как `damage`): искры, цифра и звук узнают о крите из снаряда, а не из
второго броска в момент попадания (иначе крит «мигал» бы).

Важно: `getIncomingDamage` и `findTargets` не меняются — снаряд несёт уже итоговый урон
(с учётом крита), сумма в пути точная.

### 2. Физика: тяжелее крит-снаряд

В `fireOneProjectile` масса колайдера: `PROJECTILE_MASS × config.CRIT_MASS_MULTIPLIER`
(при `isCrit`). Скорость та же — движок сам передаст больший импульс, враг сильнее
отлетает/раскачивается. Множитель 1 — крит без физической разницы.

### 3. Искры: per-instance цвет и множители

- В `Spark` добавляем поле `color` (линейный `THREE.Color`), в `SpawnParams` — `isCrit`.
- Материал становится белым (`#ffffff`), цвет каждой искры задаётся через
  `mesh.setColorAt(index, color)` (встроенный `instanceColor` InstancedMesh): обычная искра —
  `SPARKS_COLOR`, крит — `SPARKS_CRIT_COLOR`. Общий материал при этом не перекрашивается —
  финальный цвет = материал × instanceColor, а материал белый, т.е. цвет искры = её instanceColor.
- Множители крит-искр (применяются при `isCrit`):
  - `SPARKS_CRIT_COUNT_MULTIPLIER` — сколько искр рождается (Math.round),
  - `SPARKS_CRIT_SIZE_MULTIPLIER` — масштаб каждой (`size × множитель`),
  - `SPARKS_CRIT_SPEED_MULTIPLIER` — скорость каждой.
- `refreshColor` теперь перекрашивает **живые** искры по их полю `color`: обычная — заново из
  `SPARKS_COLOR`, крит — из `SPARKS_CRIT_COLOR` (иначе после смены цвета в панели старые
  instanceColor-ы остались бы прежними). Новые искры читают конфиг при рождении, как и раньше.
- `update` учитывает размер из поля искры (или множитель запоминается при рождении в `scaleMul`) —
  крит-искры крупнее, не только быстрее.

### 4. Цифры урона: цвет и кегль

В `DamageNumberParams` — `isCrit`. Для крита: `color: DAMAGE_NUMBER_CRIT_COLOR`,
`font-size: DAMAGE_NUMBER_FONT_SIZE × DAMAGE_NUMBER_CRIT_FONT_SCALE`. Тень и анимация —
как у обычных.

### 5. Конфиг (все числа здесь, раздел «КРИТЫ» после PROJECTILE_DAMAGE)

```
CRIT_CHANCE: 0.15,            // 0 — критов нет, 1 — всегда
CRIT_MULTIPLIER: 2,           // множитель урона
CRIT_MASS_MULTIPLIER: 2,      // множитель массы снаряда (физика отбрасывания)
SPARKS_CRIT_COLOR: '#ff9b3d', // оранжевые — отличаются от жёлтых обычных
SPARKS_CRIT_COUNT_MULTIPLIER: 3,
SPARKS_CRIT_SIZE_MULTIPLIER: 1.5,
SPARKS_CRIT_SPEED_MULTIPLIER: 1.5,
DAMAGE_NUMBER_CRIT_COLOR: '#ff5533', // алый
DAMAGE_NUMBER_CRIT_FONT_SCALE: 1.5,
```

Каждый параметр — с подробным учебным комментарием (как принято в проекте).

### 6. Панель настроек

- Новый раздел «Криты»: шанс (0…1), множитель урона, множитель массы.
- Множители искр критов — в раздел «Искры», кегль крита — в «Цифры урона»,
  цвета критов — в «Цвета» (рядом с их обычными собратьями).

## Проверка (скрипт `/tmp/opencode/crit-test.cjs`, без звука, DEV-хук `window.__game`)

- `CRIT_CHANCE: 1`, `PROJECTILE_DAMAGE_MIN = MAX = 10`: все цифры урона — крит-стиля
  (цвет и кегль читаются из `element.style`), урон ровно 20.
- `CRIT_CHANCE: 0`: ни одной крит-цифры, урон ровно 10.
- Шанс ~0.5 на живой волне: доля крит-цифров в разумных пределах (0.2…0.8) — бросок
  действительно случайный, не залипает.
- Регрессия: damage-range, projectile-count (и остальные звуковые — тихо, по правилу из
  сессии 13/14).
- `tsc --noEmit` + `npm run build`.

Визуал искр/отбрасывания — глазами в браузере (скриншот в ревью), автоматически цвет
instanceColor не проверяем.

## Следствия

- Первый потребитель `instanceColor` в проекте — дальше можно красить любые экземпляры
  (врагов, трупы) поштучно.
- Крит ×2 по урону и ×2 по массе: суммарный «вес» удара крита в 2 раза выше — при 15% шансе
  это заметный, но не ломающий баланс вклад (средний урон +15%).
