## Задача

Пользователь попросил разнообразить паттерны волн. Был предложен список идей, пользователь сказал
«Давай для начала то как ты предлагаешь» — то есть стартовый топ:

1. **`distance`** — параметр у ВСЕХ форм: на каком удалении от центра арены они лежат
   (сейчас все формы жёстко на `SPAWN_RADIUS` — главный источник однообразия).
2. **`ray`** — радиальный ряд (вдоль направления на куб), которого раньше не было
   (существующий `line` даёт только поперечную ориентацию).
3. **`cross`** — крест / «×» из четырёх плеч.
4. **`polygon`** — правильный многоугольник: прямые рёбра вместо дуги `circle`.
5. **`path`** — упорядоченная ломаная: точки идут по порядку опор, при `interval` враги
   «маршируют» по кривой (змейка, поезд).

Остальные идеи из списка (спираль, сетка, зеркало, градиент, внутреннее кольцо, периметр и т.д.)
**не делались** — отложены до решения пользователя, нужны ли.

## Что сделано

### `src/config.ts`

В секцию «ПАТТЕРНЫ ВОЛН» добавлены три дефолта (как и существующие
`DEFAULT_LINE_WIDTH` / `DEFAULT_CLUSTER_RADIUS` — это фолбэки для описаний волн, а не ползунки
панели):

- `DEFAULT_RAY_LENGTH: 6` — общая длина луча вдоль радиуса;
- `DEFAULT_CROSS_ARM_LENGTH: 3` — длина одного плеча креста (от центра до конца);
- `DEFAULT_POLYGON_SIDES: 4` — число сторон многоугольника, если не указано.

`SPAWN_RADIUS` (`11`) не менялся — он остаётся значением по умолчанию для `distance`.

### `src/patterns.ts`

- **`distance?: number`** добавлен к `CircleShape`, `RandomShape`, `LineShape`, `ClusterShape`
  и ко всем новым типам. Это удалённость формы от центра арены (по умолчанию `config.SPAWN_RADIUS`).
  У `ClusterShape` уже было поле `radius` (радиус самой кучки), поэтому для позиции на окружности
  спавна взяли другое имя — `distance`, чтобы не смешивать два разных радиуса.
  `getSpawnCirclePoint(degrees, distance = config.SPAWN_RADIUS)` теперь принимает радиус,
  все формы прокидывают свой `distance`.
- **Новые типы в union `Shape`** (по одному объекту-описанию + геттер + `case` в `getShapePoints`):
  - `RayShape { count, angle?, length?, distance? }` — центр ряда на точке окружности под `angle`,
    ряд идёт **вдоль радиуса** (`getScreenDirection(angle)`), от `-length/2` до `+length/2`.
    Отличие от `line` проверяется знаком отношения компонент вектора: у `ray` dx/dz ≈ 1, у `line` ≈ −1;
  - `CrossShape { count, angle?, armLength?, distance? }` — 4 плеча по экранным углам
    `angle`, `angle+90`, `angle+180`, `angle+270` (`angle = 0` — «+», `angle = 45` — «×»).
    `count` делится между плечами поровну (остаток — первым плечам), каждое плечо точки
    идёт от центра до `armLength` **наружу**, центр не занят — плечи не накладываются;
  - `PolygonShape { count, sides?, angle?, distance? }` — `count` точек вдоль **периметра**
    правильного `sides`-угольника, вписанного в окружность радиуса `distance` и повёрнутого на `angle`.
    Равномерный шаг по длине периметра: `t = index/count*sides` (в единицах рёбер), интерполяция
    внутри ребра. При `count === s > sides` точки = вершины (то же, что и `circle`), при большем
    `count` — лежат на прямых рёбрах. Сторон меньше 3 поднимается до треугольника;
  - `PathShape { count, anchors: { angle, radius? }[], distance? }` — ломаная через опоры.
    Каждая опора конвертируется в точку пола (`radius` опоры, по умолчанию `distance`),
    `count` точек кладётся **равными шагами по длине** пути: первая в первой опоре, последняя —
    в последней (`index/(count-1)*total`). Порядок массива = порядок появления при `interval`,
    отсюда «марширование». Одна опора — все точки в ней, ноль опор — пусто.
- **`ClusterShape`**: локальная переменная `distance` внутри колбэка переименована в `dist`,
  чтобы не затенять новый параметр формы.

### `src/waves.ts` — 4 демо-волны (10 → 14)

Добавлены в конец списка (проверить каждую: `?wave=N`, нумерация с единицы — новые это 11–14):

| № | Название | Что показывает |
|---|---|---|
| 11 | Крест-накрест | `cross` дважды (0° и 45°), по 12 врагов, `armLength: 4` |
| 12 | Пятиугольник | `polygon` (5 сторон, 10 точек) с `interval: 0.5` |

## Тесты

`unit/patterns.test.ts` расширено на 15 тестов (файл был 4 → стал 9 `describe`):

- `distance` у `circle` (все точки на заданном радиусе);
- `ray`: центр луча на окружности, длина = `length`, радиальная ориентация (dx/dz ≈ 1),
  фолбэк на `DEFAULT_RAY_LENGTH`, один враг = точка в центре;
- `cross`: `count = 8` → 4 точки на `armLength` и 4 на `armLength/2`, 4 конца плеч при `angle = 0`
  по осям экрана, фолбэк на `DEFAULT_CROSS_ARM_LENGTH`;
- `polygon`: `count = sides` → вершины на окружности, `count > sides` → середины рёбер на `R/√2`,
  климп сторон до 3, `distance` = радиус описанной окружности;
- `path`: точки идут по порядку от первой опоры к последней (x монотонно), первая/последняя
  точно в опорах, путь с разными радиусами вдоль одного луча (x = z, `dist` растёт),
  одна опора → все точки в ней.

Итог проверки: `tsc --noEmit` чистый, `npm test` — **69 юнит + 4 browser E2E**, `npm run build` собирается.
