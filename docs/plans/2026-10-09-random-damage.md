# Случайный урон: диапазон вместо статического числа

Дата: 2026-10-09
Статус: реализован, на прод не выложен

## Задача (дословно)

«Теперь давай поработаем с расчётом урона. Урон теперь должен быть не статическим, а задаваться двумя числами - максимальный и минимальный. Сам урон выбирается рандомно в диапазоне этих двух.»

## Решения

| Что | Решение |
|---|---|
| Конфиг | `PROJECTILE_DAMAGE` → пара `PROJECTILE_DAMAGE_MIN` / `PROJECTILE_DAMAGE_MAX` |
| Дефолты | 10…20 — средний 15, как у прежнего статического урона (баланс не сдвигается) |
| Когда бросается | При **выстреле**, не при попадании: каждый снаряд тащит свой урон (`Projectile.damage`) |
| Формула | Случайное **целое** `floor(lo + rand × (hi − lo + 1))`, равные значения — без рандома |
| Перепутанные границы | В панели min > max — при расчёте диапазон упорядочивается от меньшего к большему |
| «Урон в пути» | `getIncomingDamage` = **сумма фактических уронов** летящих снарядов (точно, а не «количество × урон») |
| Панель | Один ползунок «Урон пули» → два: «Урон, мин» / «Урон, макс» (1…200, шаг 1) |

## Изменения в коде

- `src/config.ts` — две новые опции с комментариями, правка комментария FIRE_INTERVAL.
- `src/projectiles.ts` — тип `Projectile` получил `damage`; новый `rollDamage()` (приватный);
  `getIncomingDamage` считает сумму `damage` летящих снарядов; `fireOneProjectile` бросает урон.
- `src/main.ts` — `applyHit` запоминает `damage` снаряда до его удаления и передаёт в `hitEnemy`.
- `src/settings-panel.ts` — два ползунка вместо одного.
- `src/waves.ts` — комментарии ссылаются на `PROJECTILE_DAMAGE_MIN/MAX`.

### Грабли проверки

- На волне 4 группа 2 стартует сразу после убийства группы 1 и успевает попасть в прежнее
  временное окно цифр («6 цифр вместо 4»). Фикс: наблюдатель строки «Группа N / M» в HUD —
  окно цифр режется по смене группы; смена группы происходит в начале кадра после полной

  свой порог `minDistinct`.
