# Отладочный режим: настройки не попадают в прод

Дата: 2026-10-18. Статус: реализовано (см. «Статус» в конце).

## Задача

Все наши настройки не должны попадать в прод. По умолчанию настроек нет вовсе, отладочные включаются вручную
параметром в адресе, но в проде их нет даже с параметром. К настройкам относятся панель настроек, счётчик
FPS и скорости ×8 и ×16.

Согласовано с пользователем:
- **Без `?debug` — значения из кода:** игра идёт на чистом `config.ts`, как в проде. Сохранённые правки
  панели и пресеты не теряются и снова действуют с `?debug`.
- **`?wave=N` удалить совсем** — стартовую волну в отладке выбирает селект «Волна» панели.
- **Строка «Группа N / M» — тоже отладка.** Список статов куба остаётся в игре.

## Что такое отладочный режим

- Включается параметром `?debug` в адресе (например, `http://localhost:5173/cube/?debug`) **и только
  на dev-сервере** (`npm run dev`). В прод-сборке `import.meta.env.DEV` — `false`: весь отладочный код
  вырезается сборщиком, а модули панели (lil-gui, пресеты), демо-сцены и счётчика FPS даже не попадают
  в бандл — их грузит динамический `import()` внутри ветки, которой в сборке нет.
- В тестах vitest (`MODE === 'test'`) отладка включена всегда: юниты и E2E проверяют панель и всё остальное.

В отладочном режиме — как сейчас:
- панель настроек со всеми разделами: пресеты, выбор волны, сцены (демо и полигон), параметры, звук;
- сохранённые в браузере правки конфига (и текущий пресет) применяются при загрузке;
- сохранённые наборы звуков применяются;
- счётчик FPS;
- скорости ⏸ ×0.5 ×1 ×2 ×4 ×8 ×16;
- строка «Группа N / M» под номером волны.

Без отладки (и всегда в проде):
- нет панели, демо-сцены и полигона (они открываются только из панели), нет счётчика FPS;
- скорости ⏸ ×0.5 ×1 ×2 ×4;
- конфиг — значения из кода, сохранённые правки не читаются; наборы звуков — по умолчанию;
- общий мут 🔇 остаётся и запоминается (это игровая кнопка, не отладка);
- под номером волны — сразу список статов куба.

## Устройство

- Новый модуль `src/debug.ts`: `isDebugRequested({ isDev, mode, search })` (чистая функция для теста)
  и `IS_DEBUG` — решение для текущей страницы.
- Там, где отладочный код должен исчезнуть из сборки, условие пишется как `import.meta.env.DEV && IS_DEBUG`:
  сборщик заменяет `import.meta.env.DEV` на `false` в каждом модуле и вырезает ветку вместе с её импортами.
- `config.ts` — сохранённые правки применяются только в отладке.
- `main.ts` — панель, демо-сцена и счётчик FPS грузятся динамическим `import()` только в отладке; всё,
  что с ними связано, — через `?.`. `getStartWaveNumber` удалён.
- `game.ts` — параметр `startWaveNumber` удалён, игра начинается с первой волны (`startGame(waveNumber = 1)`).
- `speed-switch.ts` — ×8 и ×16 только в отладке.
- `hud.ts` — строка группы только в отладке; `createHud` отдаёт и левый верхний блок — в него
  `upgrade-ui.ts` кладёт список статов (теперь он идёт сразу под тем, что в блоке есть, без подгонки отступа).
- `sound.ts` — сохранённые наборы читаются только в отладке.

## Тесты

- `unit/debug.test.ts` — решение `isDebugRequested`: прод — никогда (даже с параметром), dev без параметра — нет,
  dev с `?debug` — да, тесты — да.
- Существующие тесты — без изменений по смыслу (в тестах отладка включена); `startWaveNumber` из фикстуры игры убран.
- Проверка прод-сборки: в `dist` нет кода панели (lil-gui, «Настройки»), FPS и ×16; скриншот прод-сборки
  с `?debug` — ни панели, ни FPS, скорости до ×4; dev без `?debug` — то же, dev с `?debug` — всё на месте.

## Статус (2026-10-18)

Реализовано по плану. Сверх плана:
- `IS_DEBUG = import.meta.env.DEV && isDebugRequested(…)` — в сборке сворачивается в `false`, и сборщик выкидывает
  даже мелкие ветки (×8/×16, строку группы): в `dist` нет слова «debug».
- lil-gui добавлен в `optimizeDeps.include` E2E-конфига — теперь он грузится динамическим `import()`.

Проверено: в `dist` нет кода панели, демо-сцены, FPS и lil-gui (чанк vendor исчез, код игры 65 → 55 КБ);
скриншоты прода с `?debug`, dev без и с `?debug`. Воронка: tsc чистый, юниты 19 файлов / 504, E2E 11 / 35, build.
Статус: **закоммичено и отправлено в origin**, на прод не выложено.
