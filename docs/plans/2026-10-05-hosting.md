# Хостинг Project Animal на bodryanka_vpn_3 по адресу `<домен>/cube`

> **Статус:** реализовано 2026-10-05 (сессия 1). Сайт: https://farmclick.duckdns.org/cube/
> **Главное отличие от плана:** nginx на хосте не оказалось. Порты 80/443 держит **Caddy** из docker-compose
> проекта `/opt/farm`, поэтому вместо шагов 1 и 3 сделано то, что описано в разделе «Как реализовано на самом деле».

## Context
Проект — статическое SPA (Vite + TS + Three.js + Rapier), бэкенда нет. Его нужно открыть на уже существующем
домене сервера `bodryanka_vpn_3` (178.17.50.25, пользователь `serega`) по пути `/cube`.
То, что уже работает на сервере (VPN, другие сайты), не ломаем. Деплой ручной.

Rapier `-compat` встраивает WASM прямо в JS (base64), поэтому отдельный MIME-тип для `.wasm` не нужен.
Top-level `await` в коде поддерживается дефолтным build target Vite 8.

## Исходный план

1. **Разведка на сервере (только чтение):** версия nginx, `nginx -T`, кто слушает 80/443, где server-блок домена.
2. **Изменения в проекте:**
   - `vite.config.ts` с `base: '/cube/'`. Без этого `index.html` ссылается на `/assets/...`, и по адресу `/cube` скрипты не загрузятся;
   - раздел «Деплой» в `README.md`.
3. **Подготовка сервера (однократно):** `/var/www/cube` и в server-блок nginx:
   - редирект `location = /cube` → `/cube/`;
   - `location /cube/assets/` с кэшем на год (`immutable`);
   - `location /cube/` с `root /var/www`;
   - затем `nginx -t` и reload.
4. **Деплой:** `npm run build` и `rsync -avz --delete dist/ <server>:/var/www/cube/`.

## Как реализовано на самом деле

Разведка показала:
- **Веб:** nginx на хосте нет. `/opt/farm` — другой проект пользователя (farm, Vue-приложение со своим nginx внутри контейнера). Порты 80/443 занимает контейнер `farm-caddy-1` (`caddy:2-alpine`), он сам выпускает HTTPS для `farmclick.duckdns.org` и проксирует запросы в `farm:80`.
- **VPN:** контейнер `amnezia-web-ui` (AmneziaWG) на 443/udp и 51888/udp. Его не трогали.
- **Права:** `sudo` требует пароль, но `serega` в группе `docker` и владеет `/opt/farm`, так что sudo не понадобился.

Что сделано:
1. `vite.config.ts` с `base: '/cube/'`. Выбранный пользователем вариант: раздавать через существующий Caddy.
2. Сборка лежит в `/home/serega/cube` (на сервере это `~/cube`).
3. В `/opt/farm/docker-compose.yml` в сервис `caddy` добавлено монтирование `/home/serega/cube:/srv/cube:ro`.
4. `/opt/farm/Caddyfile` перед заменой проверен через `caddy validate` внутри контейнера:
   ```
   {
       servers {
           protocols h1 h2
       }
   }

   farmclick.duckdns.org {
       encode gzip

       redir /cube /cube/ 308

       handle_path /cube/* {
           root * /srv/cube
           header /assets/* Cache-Control "public, max-age=31536000, immutable"
           file_server
       }

       handle {
           reverse_proxy farm:80
       }
   }
   ```
5. Бэкапы оригиналов лежат рядом: `/opt/farm/Caddyfile.bak`, `/opt/farm/docker-compose.yml.bak`.
6. Пересоздан только контейнер caddy: `docker compose up -d caddy`. Простой farmclick — несколько секунд.

## Деплой (ручной)
```bash
npm run build
rsync -avz --delete dist/ bodryanka_vpn_3:cube/
```
Caddy после этого трогать не нужно.

## Проверка
- `curl -I https://farmclick.duckdns.org/cube` → `308` на `/cube/`.
- `/cube/` → `200 text/html`.
- `/cube/assets/*.js` → `200`, gzip, `Cache-Control: public, max-age=31536000, immutable`.
- `https://farmclick.duckdns.org/` (farm) → `200`, работает как раньше.
