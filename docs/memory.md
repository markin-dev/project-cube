## Текущее состояние (на 2026-10-07)

- **Что это:** браузерная игра «зачистка волн». Синий куб в центре арены сам стреляет раз в 0.1 с в ближайшего врага, которого летящие снаряды ещё не добьют. Враги — кубы 5 типов (`ENEMY_KINDS` в config.ts: tiny 0.4 м/0.125 кг/10 HP, small 0.6/0.42/20, normal 0.8/1/40, big 1.1/2.2/80, brute 1.5/4/120; цвет от светло-оранжевого к бордовому). Тип группы задаёт поле `enemy` в волне, без него тип каждого врага случайный — сейчас все 10 волн смешанные. Пуля вылетает из центра куба-игрока. Попадание −15, над раненым видна зелёная полоска здоровья (при полном HP скрыта), при каждом попадании всплывает цифра урона (HTML поверх canvas, `src/damage-numbers.ts`). Куб целится в 3D-точку врага (и в летящих) со смещением вверх и случайным разбросом, с упреждением только поперёк линии выстрела (`PROJECTILE_AIM_OFFSET_UP`, `PROJECTILE_AIM_SPREAD`, `PROJECTILE_LEAD`). Пули — физические тела с массой (0.15 кг, враг 1 кг): под огнём враг отъезжает и раскачивается назад, смертельная пуля опрокидывает его; погибший становится полупрозрачным серым призраком (сталкивается только с полом) и через 2 с исчезает. Арена 30×30 без стен: выбитый за край враг падает и засчитывается убитым. Враги идут волнами. 10 волн описаны вручную в `src/waves.ts` паттернами (формы `circle`/`random`/`line`/`cluster` + тайминг `delay`/`interval`). Прошёл все волны — победа, враг коснулся куба — поражение, клик/касание/пробел начинают заново.
- **ВРЕМЕННО (2026-10-07, по просьбе пользователя «для теста»):** `ENEMY_COUNT_MULTIPLIER = 3` в `config.ts` (было 5, потом 3) — в каждой группе в 3 раза больше врагов, интервал в 3 раза короче. Игра при этом проигрывается рано, это ожидаемо. Ориентиры по балансу ниже — для множителя 1. Вернуть 1, когда тест закончится.
- **Панель настроек** (`src/settings-panel.ts`, lil-gui) — доступна везде, включая прод, по умолчанию свёрнута:
  - конфиг — объект: `DEFAULT_CONFIG` (значения из кода) и рабочий `config`. Код **всегда читает `config.ИМЯ` в момент использования** — новые параметры добавлять туда же и в `SECTIONS` панели;
  - в `localStorage` (`project-animal:config-changes`) хранятся только отличия от кода. Если правка в `config.ts` «не работает», проверь шапку панели («изменено: N») и нажми «Сбросить всё»;
  - когда применяется: сразу — всё, что читается каждый кадр или выстрел, плюс цвета и гравитация через `applyLiveConfig` в main.ts; новые враги — размеры, массы, HP типов, трение, упругость, затухание, полоска здоровья; следующая волна — множитель, шеренга, кучка; перезагрузка — арена и игрок;
  - размеры врагов, пуль и полосок задаются масштабом единичных геометрий, поэтому общие геометрии не пересоздаются;
  - живых врагов правки типа не меняют — так решил пользователь (тип копируется врагу при появлении).
- **Отладка волн:** `?wave=N` в адресе начинает игру (и рестарт) с волны N. Углы в описаниях волн экранные: 0° — вверх, по часовой.
- **Баланс-ориентир для новых волн (посчитан для старых чисел: выстрел 0.15 с, урон 10, обычный 50 HP, множитель 1 — после правки пользователя пересчитать):**
  - враг идёт до куба ~5 с;
  - куб убивает врага за ~0.75 с (5 попаданий) и не промахивается: враги идут прямо на него;
  - первое убийство волны — не раньше ~0.8 с, нужны все 5 снарядов плюс полёт;
  - из появившихся разом куб успевает убить ~6;
  - если враги появляются медленнее, чем гибнут, паттерн не виден;
  - самая тесная волна — 3 (кольцо из 8 врагов за 2.8 с): при `FIRE_INTERVAL` 0.2 она уже проигрывается.

  Меняешь HP, урон или темп стрельбы — прогони все волны в headless-Chrome.
- **Стек:** TypeScript + Vite 8 + Three.js (ортографическая изометрическая камера) + Rapier (`@dimforge/rapier3d-compat`).
- **Физика:**
  - гравитация и физический пол;
  - кто с кем сталкивается — группы в `src/collision-groups.ts`;
  - пули — твёрдые тела с массой, без гравитации и с CCD, летят горизонтально на высоте ствола `PROJECTILE_HEIGHT`. Импульс от попадания считает сам Rapier, искусственных толчков и случайности нет: пользователь отверг их как «рандомные кувырки»;
  - подбирать массы и высоту удобно стендом: Rapier работает в Node (`import RAPIER from '<проект>/node_modules/@dimforge/rapier3d-compat/dist/rapier.mjs'`). Скрипт на 60 строк — пол, враг с разгоном, пули каждые 0.15 с, лог скорости и наклона после каждого попадания. Таблица результатов — в плане импакта;
  - враг управляется только на полу, с ограниченным ускорением (`moveEnemies`). Жёстко задавать ему скорость нельзя — это гасит импакт;
  - в событиях столкновений (drain) физический мир не меняем: попадания собираются и применяются после.
- **Код:** модули в `src/`, все числа в `src/config.ts`. Подробные учебные комментарии на русском — стиль проекта, их нужно сохранять.
- **Прод:** https://farmclick.duckdns.org/cube/ — там всё ещё **старая версия** (куб с прыжком). Игра с волнами на сервер не выкладывалась.

  - HP игрока вместо мгновенного проигрыша;
  - бесконечный режим или генератор волн из паттернов (сейчас список конечный — так решил пользователь);
  - новые формы (спираль, клин) — одна функция в `src/patterns.ts` плюс вариант в типе `Shape`;
  - новые типы врагов и оружия;

## Подводные камни и как с ними работать

- **Сервер `bodryanka_vpn_3`** (178.17.50.25, пользователь `serega`):
  - nginx на хосте нет. Сайт отдаёт Caddy из чужого для этого проекта docker-compose `/opt/farm`, это проект farm пользователя. Его нельзя ломать: перед правкой делать бэкап, Caddyfile проверять через `docker exec farm-caddy-1 caddy validate`;
  - VPN — контейнер `amnezia-web-ui`, не трогать;
  - `sudo` требует пароль, но он и не нужен: есть группа docker и права на `/opt/farm`.
- **SSH:** в ssh-конфиге для хоста настроен проброс порта, который бывает занят (ошибка `bind 127.0.0.1:56793`). В неинтерактивных командах добавлять `-o ClearAllForwardings=yes`, а в rsync — `-e "ssh -o ClearAllForwardings=yes"`.
- **Подпуть:** в `vite.config.ts` стоит `base: '/cube/'`. Локально `npm run preview` открывается на `http://localhost:4173/cube/`.
- **Проверка в браузере (WSL):**
  - в Linux браузера нет, CDN Playwright недоступен;
  - рабочий способ — Chrome из Windows в headless-режиме с CDP:
    ```bash
    "/mnt/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --remote-debugging-port=9333 --remote-allow-origins=* --user-data-dir='C:\Windows\Temp\cube-profile' --use-angle=swiftshader --enable-unsafe-swiftshader about:blank
    ```
    WSL видит `localhost:9333` (mirrored networking). Playwright ставится во временную папку вне проекта, подключение через `chromium.connectOverCDP('http://localhost:9333')`;
  - закрывать только через CDP `Browser.close`, **никогда** `taskkill chrome.exe` — это убьёт обычный Chrome пользователя;
  - `--virtual-time-budget` со `--screenshot` не годится: игровой цикл на rAF при этом почти не тикает.

### Сессия 3 — 2026-10-08: прицел
- Проблема (от пользователя): при малой гравитации подброшенные враги улетают вверх, а пули летели горизонтально и проходили под ними.

- Сделано:

  - смещение вверх 0.5 и случайный разброс 0.4 (доли половины размера врага, поперёк выстрела);
  - упреждение только поперёк линии выстрела;
  - промахи удаляются по 3D-расстоянию больше `ARENA_SIZE`.

  План: [`plans/2026-10-08-aiming.md`](plans/2026-10-08-aiming.md).
- Как мерить точность в браузере: считать цифры урона (MutationObserver на `document.body`) за N секунд. Куб стреляет 10 раз/с, так что попаданий/с ≈ точность × 10. Нужно ≥3 прогона на вариант: типы врагов случайные, шум ±1.
- Сравнение со старой сборкой: `git archive HEAD | tar -x -C <scratch>/old` + симлинк `node_modules` + `vite build --outDir`, раздавать `vite preview --outDir … --port 4174`. Настройки через `localStorage` (`project-animal:config-changes`) задаются отдельно для каждого порта, после теста почистить.
