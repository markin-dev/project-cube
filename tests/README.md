# E2E-тесты

Скрипты-проверки игры в реальном браузере через DevTools Protocol (CDP). Каждый скрипт
поднимает игру, крутит её, читает состояние (DOM, `window.__game`, audio-граф) и падает с
ненулевым кодом, если что-то не так. Тесты — на CommonJS (`.cjs`), потому что используют
`require`; playwright-core стоит в devDependencies.

## Что нужно запустить перед тестами

Тесты не запускают браузер и сервер сами — им нужна живая среда:

1. **Dev-сервер Vite** на `127.0.0.1:5173` (базовый путь `/cube/`):
   ```bash
   npm run dev
   ```

2. **Headless Chrome с включённым CDP** на порту `9333`:
   ```bash
   google-chrome --headless=new --remote-debugging-port=9333 --no-sandbox \
     --use-gl=swiftshader --window-size=1280,608 about:blank
   ```
   (`--use-gl=swiftshader` — программный рендеринг WebGL без GPU; путь к браузеру может
   отличаться — `chromium`, `chromium-browser` и т.п.)

## Как запускать

Все тесты сразу (проверяет готовность среды, гоняет последовательно, останавливается на первой ошибке):
```bash
node tests/run-all.cjs
```

Один тест:
```bash
node tests/crit-test.cjs
```

Подстрочный фильтр через раннер (например только криты и урон):
```bash
node tests/run-all.cjs crit
node tests/run-all.cjs enemy
```

## Важные правила

- **Тесты гоняются ТОЛЬКО последовательно.** Все они подключаются к одному Chrome по CDP и
  перебивают страницы и общий `localStorage` — параллельный запуск сломает любой из них.
  Раннер `run-all.cjs` это гарантирует.

- **Звук.** Если тест не про звук — он не должен разблокировать аудио-контекст (не делать
  `page.mouse.click`-разблокировку) иначе пользователь рядом слышит выстрелы и попадания.
  Тесты, которым звук нужен для измерений (projectile-count меряет автоматизацию гейна выстрела),
  глушат master-гейн сразу после разблокировки — в колонках тишина, измерения работают.
  Тесты звука (hit-sound, shot-death, sound-sets) — исключение: у них разблокировка сделана намеренно.

- **Криты.** Тесты, меряющие урон или логику добивания (damage-range, projectile-count), обязаны
  явно ставить `CRIT_CHANCE: 0` в `config-changes` — иначе дефолтные 15% критов удвоят часть
  попаданий и «засорят» проверки. Криты же сам проверяет `crit-test.cjs`.

- **DEV-хук.** Тесты читают/меняют тела врагов напрямую через `window.__game` — это хук в
  `main.ts` внутри `if (import.meta.env.DEV)`, в прод-бандле его нет. Поэтому тесты работают
  только на dev-сервере, не на собранном `dist/`.
